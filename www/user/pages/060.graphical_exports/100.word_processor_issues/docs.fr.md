Hélas, hélas, hélas, le copier/coller et l'inclusion graphique sont bien plus complexes qu'ils ne devraient l'être, du fait d'un manque généralisé de coopération entre les principaux acteurs du domaine. Nous discutons donc ici des problèmes liés à des traitements de texte spécifiques (et à des logiciels similaires).

## Choix de format pour les applications Mac

À ce jour (21 avril 2016) :

* Word 2011 pour Mac a commencé (enfin) à accepter le copier/coller de textes RTF contenant des images (la manière « standard » pour JSesh d'effectuer un copier/coller), et il accepte maintenant le format EMF dans ceux-ci. Le PDF n'est plus la « meilleure » solution, car les images PDF ont tendance à être mal recadrées.
* Sur Word 2008, les formats utilisables sont RTF et PDF, le PDF donnant les meilleurs résultats. Il semble que l'on puisse utiliser des images « EMF » dans l'export RTF. EMF donne de bien meilleurs résultats que MacPict.
* Sur Word 2004, seul le RTF est raisonnable. Il doit être configuré pour utiliser des images MacPict.
* Sur Nisus et Mellel, on peut utiliser soit le PDF, soit le RTF. Comme le PDF conserve ses commentaires, il est possible de copier-coller vers et depuis JSesh. Pour le RTF, vous devez utiliser MacPict comme format de sortie.
* Sur OpenOffice/NeoOffice, le PDF ne fonctionne pas encore, il faut donc utiliser le RTF. Le format d'image suggéré est EMF (avec de meilleurs résultats graphiques).
* Pour les logiciels non orientés texte (comme PowerPoint ou Keynote) : utilisez le PDF.


## Choix de format pour les applications Windows

* Pour Word ou OpenOffice Writer : utilisez le RTF, avec EMF comme format graphique. Vous pouvez également utiliser directement EMF.
* Pour les logiciels non orientés texte (comme PowerPoint) : utilisez EMF.

## Choix de format pour les applications Linux

Pour OpenOffice et consorts : utilisez le RTF, avec EMF comme format graphique.
